# Kakuro

> Crossword rules for a grid of numbers — every run adds up, and no run repeats a digit.

**At a glance** · Solo · one puzzle, one answer · 10–25 min · Play it under **Logic** (`/logic`).

## What it is

Kakuro is often called "cross-sum" — it looks like a crossword, but instead of letters spelling words, runs of white cells hold digits that must sum to a printed clue. The twist that makes it a logic puzzle rather than simple arithmetic is the **no-repeat rule**: every digit in a run must be distinct, which turns "what adds up to this number" into a much sharper deduction once you know how many cells you're filling.

That distinctness rule is doing more work than it looks like at first glance. Plenty of digit combinations can sum to a given clue, but once you also require every digit to be different, most sums over a fixed number of cells collapse down to just one or two possible digit sets — arithmetic becomes elimination almost by accident. As with every puzzle in the Logic Lab, a valid Kakuro board has exactly one digit assignment satisfying every clue at once.

## Goal

Fill every white cell with a digit **1–9** so that **every horizontal run and every vertical run contains no repeated digit** and **sums to the clue printed in the black cell that starts it**. Every run in the grid has to hit its target simultaneously — there's no partial credit for a run that sums correctly but repeats a digit, or vice versa.

## The grid & clues

The board is a fixed **7×7** grid. The entire top row and entire left column are always black **clue cells**; scattered black cells also appear through the interior to break the white cells into runs. Each black cell can show two numbers: a **right** clue (the sum of the across-run immediately to its right) and a **down** clue (the sum of the down-run immediately below it). A run can never be longer than 9 cells, since it needs that many distinct digits from 1–9.

Because the border row and column are always black, every white cell in
the grid belongs to exactly one across-run and one down-run — there's
no white cell floating without a clue in either direction, which is
part of what keeps the puzzle uniquely solvable.

## Rules

1. White cells hold a single digit from **1 to 9**.
2. Every maximal horizontal run of white cells sums to the **across (right) clue** in the black cell immediately to its left.
3. Every maximal vertical run of white cells sums to the **down clue** in the black cell immediately above it.
4. **No digit repeats within the same run** — but a digit can appear in both the across-run and the down-run passing through the same cell, since those are separate constraints.
5. Runs never exceed **9 cells** (there are only nine distinct digits to use).
6. A well-formed puzzle has exactly one digit assignment satisfying every run simultaneously.

Rule 4 trips up more players than any other: it's tempting to treat a cell's
digit as globally unique the way Sudoku does, but Kakuro only cares about
uniqueness *within* the specific run being summed. Two runs sharing a cell
are otherwise completely independent constraints that just happen to
overlap at that one square.

## How it works in ChessRetabled

- **Opening a puzzle.** Under **Logic**, choose Kakuro. The board is generated by first sketching the black-cell layout (top row and left column always black, plus roughly one interior cell in eight), then filling every run with a distinct-digit solution before sums even exist. Each run's clue is derived directly from that filled solution's own total, and the whole puzzle is checked for a unique reconstruction before it's shown to you.
- **Filling cells.** Select a white cell, then tap a digit **1–9** on the pad to place it (tap the same digit again, or the eraser, to clear it). Cells that break a run — a repeated digit, a sum already over the clue, or a completed run whose total doesn't match — are flagged red live.
- **The 💡 hint.** Every generated puzzle stores its full solution, so a hint never re-solves anything. Press **Hint** for a *nudge* — the first wrong or empty white cell lights up; press again to *reveal* its correct digit. Using a hint marks the puzzle **assisted**.
- **Completion.** Every run correctly summed and digit-distinct logs the solve to your archive.
- **Starting over.** **New puzzle** replaces the whole board and clue layout, not just the digits — the black-cell pattern itself changes too.

## Strategy

Kakuro rewards players who treat each run as its own tiny puzzle first,
then use the crossings between runs to merge those tiny puzzles into one
solved grid.

### Beginner — memorise the locked combinations
- **Two-cell locks.** Some length-2 sums have only one possible digit *set*: 3 → {1,2}, 4 → {1,3}, 16 → {7,9}, 17 → {8,9}. The pair of cells will hold exactly those two digits — you just need the crossing clues to tell you which cell gets which.
- **Extreme sums are nearly forced.** A run of length *k* has a minimum possible sum of 1+2+…+*k* and a maximum of (10−*k*)+…+9. A clue sitting at or near either extreme leaves very few digit sets to try — a 3-cell run summing to 24 can only be {7,8,9}, the maximum.
- **Solve the tightest runs first.** Short runs with extreme sums crack fastest and hand you concrete digits to feed into their crossing runs.
- **Scan the whole board before committing.** A run that looks ambiguous in isolation often has only one workable option once you notice its crossing runs are already half-determined elsewhere.

### Intermediate — cross-reference runs
- **Intersect candidate sets.** At the cell where an across-run and a down-run cross, take the digits still possible from each run's remaining combinations and keep only the ones common to both — this often collapses a cell to a single digit well before either whole run is solved.
- **Subtract as you fill.** Once part of a run is placed, subtract those digits from its clue and treat the empty remainder as a smaller Kakuro sub-problem with fewer cells and a smaller target sum.
- **Reuse a solved run's digit set.** Even before you know cell order within a run, knowing its digit *set* lets you cross those specific digits against a crossing run's own combination list, ruling out combos that can't share a value at the intersection.
- **Track which digits a run has already ruled out.** A run with three cells filled and only one unfilled has a single remaining valid digit — the clue's sum minus what's already there, as long as that digit isn't already used in the run.

### Advanced — chain and account
- **The 45-rule.** A run of 9 cells uses every digit 1–9 exactly once and always sums to 45. When a run almost spans an entire block and you know the totals of the runs around it, subtracting from 45 can pin down a single stubborn cell.
- **Cascade from locked runs.** Solving one small, near-unique run often shrinks a neighbouring run's remaining sum into another near-unique combination — always re-derive each affected run's target after every placement rather than re-scanning the board from scratch.
- **Compare combo pairings at intersections.** When two long runs cross, list each one's feasible combinations and check which single digit value is consistent across *every* valid pairing between them — that digit is forced at the intersection even if neither run is fully solved yet.
- **Work backward from a nearly-solved neighbourhood.** When a cluster of runs around a stubborn cell are all otherwise resolved, the one remaining unknown is usually pinned by simple subtraction rather than combinatorics — save the raw combination-hunting for genuinely open stretches of the board.
- **Use the border cells as fixed anchors.** Since the top row and left column are always black, every run you're solving has a definite start; orient your combination lists from that anchor outward rather than guessing at where a run begins mid-grid.

## Traps & common mistakes

- **Applying "no repeats" across directions.** The distinct-digit rule is per run, not per cell — the same digit can legally appear in both the across-run and the down-run that cross at one cell.
- **Mixing up right and down.** "Right" is the across-clue for the run starting immediately to that black cell's right; "down" is the down-clue for the run immediately below it — swapping them misapplies a sum to the wrong stretch of cells.
- **Hunting combos beyond 9 cells.** The generator never creates a run longer than 9 — if a stretch looks longer, you've likely missed a black cell splitting it.
- **Fixing a digit set without ordering it.** Knowing a run must use {2,4,7} doesn't tell you which cell gets which value — always resolve that with the crossing run before committing.
- **Forgetting to update a run's remaining sum.** After placing a digit, the run's target effectively shrinks; solving the rest of that run against the *original* clue instead of the remaining balance is a common source of wrong entries.

## A worked example

```
[4→] . .
```

A black clue cell shows an across-sum of **4** starting a
two-cell run. The only two distinct digits from 1–9 that sum
to 4 are **1 and 3** (2+2 would repeat a digit, which Kakuro
forbids). If a down-clue crossing the first of those two cells
shows **1** — meaning that cell's own down-run is just itself,
equal to 1 — the first cell is pinned at 1 outright, which
forces the second cell to 3.

Notice that the down-clue did all the real work here: the
across-clue alone only narrowed the pair down to a two-element
set, {1, 3}, without saying which cell gets which value. It's
the crossing clue that breaks the tie — a pattern worth watching
for throughout the grid.

## Glossary

- **Run** — a maximal line of consecutive white cells in one direction (across or down).
- **Clue** — the number in a black cell giving the target sum for the run(s) it starts.
- **Locked combo** — a sum/length pairing with only one possible digit set.
- **Distinct digits** — no digit repeats within a single run.
- **Remaining balance** — a run's clue minus the digits already placed in it, the target for its still-empty cells.
- **Border cell** — any cell in the always-black top row or left column; it only ever carries clues, never a digit.

## Where to go next

Like the "each digit once" backbone? **Sudoku** is the purest version of that idea without the arithmetic, **KenKen** keeps Kakuro's summing but arranges cells into free-form cages instead of straight runs, and **Suguru** swaps sums for touching-adjacency exclusion over similarly irregular regions.

All three ask the same underlying question Kakuro does — "given this shape and this constraint, which digits are even possible here?" — just with a different shape and a different constraint each time.

If the arithmetic itself is what hooks you, KenKen is the closest relative
of the group: its cages can use subtraction, multiplication, and division
as well as addition, so the combination-hunting habits you build here
transfer almost directly.
